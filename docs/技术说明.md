# 技术说明

## 1. 项目概述

“灵动手势收藏屋”是一个完全运行在浏览器端的实时手势交互应用。项目使用 TensorFlow.js 调用 MediaPipe Hands 模型，从摄像头画面中检测手部关键点，并将识别结果用于字母编码、双手计数、语音播报和动态物品抓取。

核心功能：

- 实时检测最多两只手的 21 个关键点，并在画布上绘制骨架。
- 三模式切换：字母识别、收藏品抓取、摄像头画面球体抓取。
- 握拳强制识别为0，并使用掌宽与拇指相对位置避免拳侧拇指误计数。
- 手指数统计与 A—Z 编码：单手 1—5 指映射 A—E，双手指数直接拼接为两位数（1—26 映射 A—Z）。
- 双模式物品布置：手势捏合抓取拖动，或鼠标/触屏直接拖拽。
- 球体增强现实交互：多颗彩色高光球叠加在视频容器中，循环从顶部下落并从底部离场，不设置地面碰撞；支持托举、拍击、捏合抓取、侧边碰撞和球间碰撞。
- 抓取成功时弹出专属反馈动图并中文播报物品名称；字母稳定变化时英文播报。
- 单屏响应式工作台界面，配套 GIF 动图与“线条小狗”静态素材装饰。

## 3. 系统结构与数据流

```text
摄像头视频（字母/收藏模式优先1280×720，球体模式优先720×1280，30fps）
   ↓
MediaDevices.getUserMedia
   ↓
MediaPipe Hands（每只手 21 个关键点，最多 2 只手）
   ├── 手指数统计 → 分侧 6 帧多数表决 → 拼接编码 → A—Z → 英文播报
   ├── 拇指-食指捏合距离判断 → 捏合中点坐标 → 收藏品/视频球体抓取与释放
   ├── 鼠标/触屏 Pointer Events → 抓取/释放 → 物品移动（指针）
   └── Canvas 渲染 → 骨架与关键点显示
```

检测循环基于 `requestAnimationFrame`，每帧执行：

```text
estimateHands(video, { flipHorizontal: true })
   ↓
清空画布 → 绘制骨架与关键点
   ↓
有手：analyzeGesture(hands[0]) → analyzeLetters(hands) → updateInteraction(hands[0])
无手：重置手势/计数/字母/平滑历史与播报去重状态
   ↓
状态栏显示“检测到 N 只手” → 进入下一帧
```

## 4. 模块实现细节

### 4.1 main.js — 应用入口与生命周期

- `init()`：页面 `load` 后执行——生成 A—Z 字母表、绑定摄像头按钮与三个模式按钮、初始化默认字母模式，再异步初始化手部检测模型。
- `setMode(mode)`：在 `letters / collection / ball` 间切换，更新模式面板、标题、提示和交互状态，并释放上一个模式正在抓取的对象。
- `toggleCamera()`：摄像头开关。启动流程为 `setupCamera → detectHands`，成功后按钮文案切换为“关闭摄像头”；关闭流程为 `stopCamera → stopDetection`。
- `setConnectionDot(online)`：切换“本地实时识别”状态灯——摄像头与检测运行中为绿色，关闭或启动失败为红色。

### 4.2 camera.js — 摄像头管理

- `setupCamera(video, canvas, mode)`：字母与收藏模式优先请求1280×720横屏画面，球体模式优先请求720×1280、9:16竖屏画面；将媒体流挂到 `video.srcObject`，并把画布尺寸同步为视频实际尺寸。
- `updateCameraMode(video, canvas, mode)`：摄像头开启后切换模式时通过 `MediaStreamTrack.applyConstraints` 更新目标比例，不重启检测循环；不支持竖屏的设备自动保留其可用比例。
- `stopCamera(video)`：停止全部媒体轨道、清空 `srcObject`、复位 `isCameraOn`。
- 模块以 `export` 形式输出 `isCameraOn`，供主流程判断当前摄像头状态。

### 4.3 detector.js — 检测循环与平滑

- 模型初始化：使用 `runtime: 'mediapipe'`、`modelType: 'full'`、`maxHands: 2`，检测与跟踪置信度均为0.4；运行时资源从 `public/mediapipe/hands/` 本地加载。
- 单帧检测使用 `estimateHands(video, { flipHorizontal: true })`，与镜像后的摄像头画面保持一致，保证左右方向判定正确。
- 手势判定：根据掌宽动态计算拇指尖与食指尖的捏合阈值，并使用“进入阈值/释放阈值”迟滞区间，比固定像素阈值更适应手离摄像头的远近，也避免关键点抖动造成频繁掉球；交互位置取两指指尖中点，使抓取位置与真实捏合位置一致。
- 握拳结果不参与普通多数表决：当前帧确认五指均收拢时立即清空历史并输出0，避免上一手势短暂残留。
- 识别平滑：`SMOOTH_WINDOW = 6`，左右两侧手指数各维护长度 6 的滑动窗口（`leftCountHistory` / `rightCountHistory`），每帧做多数表决（`modeOf`）后再拼接编码，降低关键点抖动引起的数字跳变。
- 字母播报：`lastSpokenLetter` 记录上一次播报的字母，仅当字母变化且不为“—”时调用 `speakEnglishLetter`，避免连续重复播报。
- 无手分支：清空平滑窗口与播报去重记录，识别面板复位为 0 与“—”。

### 4.4 gesture-recognition.js — 手指判定与编码

- 四根长手指通过“指尖到手腕”与“中间关节到手腕”的距离比例判断是否伸直。拇指额外比较拇指尖与食指掌指关节、掌宽和拇指关节的位置；四根长手指均弯曲且拇指收在掌内时明确输出0。
- 分指判定比例（`FINGER_EXTENSION_RATIOS`）：

| 手指 | 判定比例 | 说明 |
| --- | --- | --- |
| 食指 `index_finger_tip` | 1.16 | 中等长度手指 |
| 中指 `middle_finger_tip` | 1.16 | 中等长度手指 |
| 无名指 `ring_finger_tip` | 1.12 | 偏短手指，适当放宽 |
| 小指 `pinky_finger_tip` | 1.05 | 最短手指，伸直时指尖增幅最小，需明显放宽 |

- 小指单独放宽的原因：小指骨节长度最短，完全伸直时“指尖相对中间关节的增幅”本身就小，统一使用大比例（如 1.18）会把伸直的小指误判为弯曲；手指真正弯曲时比值会降到 1.0 以下，因此放宽阈值不会把弯曲误判为伸直。
- `recognizeAlphabet(hands)`：
  - 0 只手：返回全零与字母“—”。
  - 1 只手：按该手的手指数编码。
  - 2 只手：因为摄像头画面已镜像，按手腕横坐标排序区分左侧手与右侧手（不依赖设备的左右手标签）。
- `fingerCountToLetter(count)`：1—26 依次映射 A—Z，超出范围返回“—”。

### 4.5 interaction.js — 抓取与拖拽

手势抓取：

- `updateInteraction(hand, canvas, currentGesture, handPosition)`：收藏模式把捏合中点映射到收藏台，球体模式则映射到视频容器；字母模式关闭抓取光标。球体模式按竖屏 `cover` 的实际缩放与裁切偏移换算坐标，即使电脑摄像头输出横屏画面，手与球的位置仍能准确对应。虚拟光标抓取态为红色、张开态为绿色。
- 多颗球体使用 `.video-gesture-ball` 叠加在 `.video-container` 内，与Canvas骨架共用摄像头坐标。独立动画循环计算重力、侧边反弹、底部离场和球间弹性碰撞；张掌掌心可形成托举面，快速移动手掌会向球体施加拍击冲量，捏合则进入抓取拖动状态。
- 张掌拍击使用整只手的21个关键点构成碰撞轮廓，不再只依赖单一掌心点；手指、指节或掌缘触球均可响应，并对短暂检测漏帧保留约260毫秒的交互状态。
- 抓取时粒子向球心聚拢并触发柔软形变，释放和拍击时粒子向外扩散。球体模式不调用收藏品反馈弹窗和名称语音，避免遮挡摄像头交互。
- 单手捏合距离映射到CSS缩放变量，实现连续软体挤压；释放时继承经过平滑的手掌速度，实现方向和力度相关的抛掷惯性。
- 两只手同时捏合时，以两捏合点中点控制位置，以两点距离控制横向拉伸，以连线角度控制球体旋转。
- 握拳状态产生以掌心为中心的距离衰减吸引力场；张掌用于托举和速度碰撞；单独伸出食指时改用食指尖作为控制点完成精确点按。所有控制均由实时关键点坐标直接映射，不使用预录动画模拟手势。
- 球速超过阈值时按时间间隔生成渐隐圆形轨迹，直观表现抛掷和拍击的方向与速度。
- 目标圈只接受 `touched` 状态的球，避免自然下落球自动计分；命中后累计分数、触发粒子并重置球体循环。
- 连续力场：`liveHandState` 记录手掌速度、旋转角速度、五指张幅和掌面倾角。张幅映射力场半径，角速度映射切向涡流，低速移动映射黏性吸附，掌面倾角映射横向滚动力。
- 双手空间：`dualHandState` 记录两掌距离及变化速度，以两掌中点为中心向球群施加径向压缩/膨胀力；两只张掌作为传送门端点，两掌连线同时构成可碰撞能量绳。
- 材质系统：每次球体重生随机选择 `water / gel / glass / fire / magnet / bubble`。材质配置分别控制重力、空气阻尼、碰撞恢复系数、漂浮、磁力与易碎属性，CSS材质类负责对应的视觉表现。
- 融合与分裂：经过触碰、材质相同且相对速度较低的软材质球按面积合并；双手捏合拉伸记录峰值，超过阈值后克隆并生成两颗具有分离速度的小球，同时设置冷却时间防止立刻再次融合。
- 指尖轨迹：食指点按状态以约38毫秒间隔记录轨迹点，球体吸附到最近轨迹并朝后续点运动；轨迹首尾接近且宽高达到阈值时生成短时环形轨道。
- 身体碰撞：`body-tracking.js` 使用 MediaPipe BlazePose Lite（本地资源）以低于手部检测的频率估计33个身体关键点，再将肩、肘、腕、髋和膝连接为线段碰撞体。球心到线段最近点的距离用于碰撞分离、反弹和沿肢体滚动。
- 抓取命中：光标与物品中心距离小于 50 像素即抓取成功，记录“光标相对物品左上角”的偏移量 `grabOffset`，并触发反馈动图与延迟 500ms 的中文播报。
- 移动与释放：抓取中每帧按偏移量更新位置；张开手势时释放。

鼠标/触屏拖拽（Pointer Events）：

- `pointerdown`：命中 `.object` 时记录指针相对物品左上角的偏移，添加 `grabbing` 高亮类，调用 `setPointerCapture`，并先释放手势正抓着的物品，避免双输入冲突。
- `pointermove`：复用与手势相同的 `moveObjectTo` 更新位置；鼠标按键已松开（如在窗口外释放）时自动结束拖拽。
- `pointerup / pointercancel / window blur`：统一结束拖拽，移除高亮并释放指针捕获。
- 冲突防护：指针拖拽期间（`pointerDrag` 非空）暂停手势对物品的抓取与移动，保证两种输入互不干扰。

位置与层级：

- `moveObjectTo(element, left, top)`：以 `clientWidth / clientHeight`（内容盒）减去物品尺寸作为上限钳位，物品不会被拖到收藏台外，也不会压住面板 1px 边框。
- `bringToFront(object)`：清空其它物品的行内 `z-index` 并当前物品置顶（`z-index: 6`），手势与鼠标抓取共用。
- 触屏拖拽期间页面不会滚动（`.object { touch-action: none; }`）。

### 4.6 renderer.js — 关键点渲染

- `HAND_CONNECTIONS` 定义 21 个关键点之间的骨架连接（手腕—各指关节、掌骨横连接）。
- `drawHands`：先画连接线（白色半透明、圆头），再画关键点圆点，按部位着色——手腕紫色、拇指红色、食指蓝色、中指绿色、无名指橙色、小指黄色。
- 另外提供 `drawFingerConnections`（单指高亮）与 `drawHandOutline`（简化手掌轮廓）工具函数。

### 4.7 utils.js — 面板刷新

- `updateStatus` / `updateInteractionStatus`：刷新检测状态与手势状态文本。
- `updateRecognitionStatus(fingerCount, letter, details)`：
  - 顶部大数字显示最终编码（与字母一致：单手 1—5，双手为拼接数字）。
  - “双手加数”行显示 左 + 右 = 总数。
  - “字母编码”行：两侧都有手指数时显示“2 与 3 → 23”，一手为 0 时退化为单数字“3 → 3”。
  - 同步高亮 A—Z 字母表中当前命中的字母格。

### 4.8 voice.js — 语音合成

- `initSpeechSynthesis()` 返回两个方法，并统一处理语音列表加载（`getVoices` + `onvoiceschanged` + 1000ms 超时兜底）。
- `synthesizeSpeechSentenceBySentence`：中文播报（过滤 `zh` 前缀音色，`zh-CN`，语速 1.2），返回 Promise 等待播报结束，用于摄像头开关与抓取提示等流程。
- `speakEnglishLetter`：英文播报（优先 `en-US` 音色，语速 0.82，音调 1.05，播报前 `cancel` 打断上一条），仅接受单个 A—Z 字母。
- 物品中文播报与字母英文播报互相独立，互不打断。

## 5. A—Z 编码规则（详表）

单手模式：伸出 1—5 根手指分别识别为 A—E。

双手模式：将两侧手指数直接拼接成两位数再映射字母：

```text
编码 = 左侧手指数拼接右侧手指数（左侧 2 根、右侧 3 根 → 23 → W）
```

- 任意一侧为 0 根时，退化为另一侧的手指数进行单手识别。
- 有效拼接编码与字母对应关系：

| 拼接 | 11 | 12 | 13 | 14 | 15 | 21 | 22 | 23 | 24 | 25 |
| --- | --- | --- | --- | --- | --- | --- | --- | --- | --- | --- |
| 字母 | K | L | M | N | O | U | V | W | X | Y |

- 其余拼接（31—55）超出 1—26 范围，显示“—”。
- 独立显示“双手加数”（左 + 右 = 总数），与拼接编码互不影响。
- 编码结果经分侧 6 帧多数表决后输出；字母稳定变化时才触发英文播报。

常用示例：

| 目标字母 | 左侧手 | 右侧手 | 编码 |
| --- | --- | --- | --- |
| A | 1 | 0 | 1 |
| B | 2 | 0 | 2 |
| L | 1 | 2 | 12 |
| O | 1 | 5 | 15 |
| W | 2 | 3 | 23 |
| Y | 2 | 5 | 25 |

## 6. 界面与样式体系

### 6.1 单屏布局

- `body` 为纵向 flex 100vh 布局，页面主体分为：hero（标题区）、workspace（双列工作台：手势镜头 + 动态收藏台）、guide（三步说明）、footer。
- 工作台使用 CSS Grid 双列：`minmax(360px, .88fr)` 与 `minmax(520px, 1.25fr)`，宽屏并排放置，窄屏堆叠为单列。
- 视频画面容器使用 `height` 基准 + `min-height` 兜底 + `flex: 1 1 auto`，在有剩余空间时向下撑开，空间不足时自动收缩，避免内容溢出。

### 6.2 收藏台与物品

- 收藏台区域（`.interaction-area`）为相对定位容器，内含网格背景（`.stage-grid`）、区域标题（`.stage-title`）、8 个收藏品（`.object`）与线条小狗摆件（`.stage-pup`）。
- 收藏品初始位置为“错落”百分比坐标（各行上下错位、各列左右不齐），避免整齐网格感；物品被拖动后位置转为行内像素值，刷新页面恢复初始错落布局。
- 物品层级：网格背景 < 小狗摆件（`z-index: 1`）< 收藏品（`z-index: 2`）< 虚拟光标（`z-index: 10`）。拖动中的物品通过 `bringToFront` 置于最上层。
- 抓取态样式（`.grabbing`）：变色边框、光晕与呼吸动画（`grabPulse`）。

### 6.3 装饰体系

| 装饰 | 素材 | 位置 |
| --- | --- | --- |

### 6.4 状态灯

- “本地实时识别”文字前有状态圆点（`#connectionDot`）：
  - 红色 `#e5484d`（`.dot-offline`）：未连接——初始状态、摄像头关闭或启动失败。
  - 绿色 `#22c55e`（`.dot-online`）：已连接——摄像头启动、检测运行中。
- 颜色使用固定色值，不受主题变量覆盖影响。

### 6.5 主题与响应式

- 主题变量集中在 `:root`（背景、面板、边框、文字、强调色），文件末尾的“黑白主题”段以白底黑字覆盖全局配色，GIF 与静态素材保留少量原色作为视觉焦点。
- 响应式断点：

| 断点 | 变化 |
| --- | --- |
| `max-width: 1180px` | 隐藏两侧贴纸栏 |
| `max-width: 1050px` | 工作台改为单列，收藏台保证最小高度 |
| `max-width: 720px` | 移动端：物品放大为 116px、两列错落排布、隐藏面板贴纸与收藏台摆件、页脚纵向排列 |
| `max-height: 820px` 且 `min-width: 1051px` | 紧凑版：压缩全页空隙与字号、视频容器与收藏品缩至 88px、装饰同步缩小（适配 125% 缩放或矮窗口） |

## 8. 隐私与运行方式

视频帧、手部关键点、身体关键点和识别结果均在浏览器本地处理，不上传到业务服务器。首次使用时只需要授予当前本地网页摄像头权限。MediaPipe Hands 与 BlazePose 运行时资源分别保存在 `public/mediapipe/hands/` 和 `public/mediapipe/pose/`，不依赖外部模型地址。

开发服务器由 Vite 提供，默认地址为 `http://localhost:5173/`（端口被占用时 Vite 会自动顺延，例如 5174）。

生产构建：

```powershell
npm run build
```

构建产物输出到 `dist/` 目录，可部署到任意静态服务器。

## 9. 开发与验证实践

- 纯逻辑模块（手指判定、编码映射）可直接用 Node.js 加载测试：构造带命名关键点的对象，断言手指数与编码结果，覆盖“小指伸直 / 半弯”“五指全伸 / 全弯”“左右拼接”等边界。
- 界面与交互使用浏览器 DOM 冒烟验证：断言收藏品数量、初始位置无重叠与不越界、拖拽后位置更新与边界钳位、状态灯颜色、素材加载成功等。
- 响应式断点可用 iframe 技巧验证：iframe 内部拥有独立视口，媒体查询按 iframe 尺寸计算，可模拟移动端（500×900）、单列（1024×800）与用户环境（1536×816）等尺寸，无需改变开发机窗口。
- 指针拖拽可通过派发 `PointerEvent`（`pointerdown → pointermove → pointerup`）走真实事件链验证，不依赖人工鼠标操作。
