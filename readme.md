# 灵触 AirTouch

灵触（AirTouch）是一款基于 TensorFlow.js 与 MediaPipe Hands 的浏览器端实时手势交互应用。

- 项目维护者：李雨
- 学号：420231159029

## 项目功能

页面顶部提供“字母识别、收藏品抓取、球体抓取”三个模式按钮，三项功能互相独立，可随时切换。
字母编码面板只在“字母识别”模式显示和运行；进入收藏品或球体模式后会暂停字母计算与英文播报，为摄像头交互留出更大的显示区域。

### A—Z 字母识别

- 握拳时立即识别为数字 0；拇指收在掌内不会再被误算为伸出。
- 单手伸出 1—5 根手指时，分别识别为 A—E。
- 同时检测两只手时，按画面位置区分左侧手和右侧手。
- 页面实时显示双手加数：`左侧手指数 + 右侧手指数 = 总手指数`。
- 字母编码为两侧手指数的拼接：例如左侧 2 根、右侧 3 根拼成 `23`。
- 拼接数字 1—26 依次映射为 A—Z，超出范围显示“—”。
- 字母稳定变化后，通过 Web Speech API 使用英语播报识别结果。

示例：

| 左侧手 | 右侧手 | 拼接数字 | 字母 |
| --- | --- | --- | --- |
| 2 | 3 | 23 | W |
| 1 | 5 | 15 | O |
| 2 | 5 | 25 | Y |
| 4 | 2 | 42 | — |

### 动态收藏品抓取

项目保留原有的捏合抓取交互：

- 拇指和食指捏合：抓取物品。
- 移动手掌：拖动物品。
- 拇指和食指张开：释放物品。
- 成功抓取时播报真实物品名称。
- 也可以直接用鼠标（或触屏）拖动收藏品，自由布置摆放位置。

收藏台中的物品包括：

- 彩虹棒棒糖
- 惊喜礼盒
- 向日葵花束
- 爱心抱枕
- 节拍耳机
- 守护天使
- 庆祝彩带
- 魔法星星

每种物品均使用本地 GIF 动态素材，并配置了与物品语义对应的专属弹出回应动图。

### 摄像头球体抓取

- 切换到“球体抓取”后，9颗彩色高光球从实时摄像头画面顶部循环下落；数量和下落速度均在上一版基础上提高约50%。球不会撞击地面，而是从底部离场消失，再重新从顶部进入。
- 捏合时使用拇指尖与食指尖的中点作为抓取点；张掌时使用掌心作为托举和拍击位置。
- 张开手掌可从下方托举，快速挥手可弹性拍开球体；捏合两指可抓住，移动手掌可拖动，张开两指释放。
- 球体具有重力、侧边碰撞和球间碰撞，抓取、释放与拍击时显示星芒、光带、光晕拖尾和双层冲击环，不触发收藏品弹窗或名称播报；也支持鼠标或触屏拖动测试。
- 两只手的21个关键点都会连接成指骨胶囊和实心掌面碰撞体。关键点使用速度自适应平滑与短时位置预测，球体按真实接触位置计算法线、穿透修正、弹性冲量、手速传递和切向摩擦，因此托举、拨动、扫动与拍击具有不同力度和方向，未接触时不会凭空弹开。
- 球体模式支持真实隔空控制：握拳产生吸引力场，张掌可托举或拍击，单独伸出食指可轻触弹球；单手捏合会根据指距产生软体挤压，移动后释放会继承手速形成抛掷；双手同时捏合可拉伸和缩放球体。高速运动时会产生渐隐轨迹。
- 摄像头画面内设有空中目标圈。只有经过手势控制的球进入目标圈才计分，成功后显示粒子并重新生成球体。
- 在保留上述交互的基础上，球体模式加入“数字生命场”：张掌产生连续斥力，握拳产生引力，旋转手掌形成涡流；手掌张开幅度控制范围，移动速度、捏合强度和掌面倾斜连续改变球体运动。
- 双手之间形成能量绳；双手靠近或展开会压缩、膨胀整个球群。两只张开的手掌构成空间传送门，球靠近一侧后从另一侧出现。
- 球体随机获得水球、果冻、玻璃、火焰、磁力或泡泡材质，每种材质具有不同的重力、阻尼、弹性、漂浮、磁力或碎裂反应。
- 同材质软球在经过手势控制后低速碰撞可融合成长；双手捏合拉伸超过阈值后会分裂为两颗小球。
- 本地 BlazePose 姿态模型识别肩、肘、腕、髋与膝，球体可与身体和手臂轮廓碰撞并沿肢体方向滚动。
- 球体拥有好奇、害羞、开心、平静、调皮、生气和孤独状态：会主动靠近、躲避、绕手运动、受击变得生气，长时间未互动则主动寻找用户。
- 单独伸出食指可绘制发光路径，附近球体会跟随轨迹；轨迹闭合为圆后会形成短时环形轨道。

## 个性化设计

- 项目名称、标题和页脚均围绕手势交互主题设计。
- 重新设计为白色背景、黑色文字的单屏手势交互工作台界面。
- 标题区、摄像头区、收藏台、使用说明和抓取弹窗均使用动态表情素材。
- 收藏品错落摆放，两侧贴纸栏、收藏台角落与页脚搭配“线条小狗”静态素材装饰；三个功能界面共享保留素材原色的背景贴纸，贴纸位于所有主面板下层，不遮挡实时画面和操作组件。
- 显示完整 A—Z 字母表，当前识别字母会高亮。
- 使用 6 帧多数表决平滑两侧手指数，减少字母跳动。
- 模型与视频数据均在浏览器本地处理。

## 使用流程

1. 使用 Chrome 或 Edge 打开页面，点击“启动摄像头”，并允许浏览器访问摄像头。
2. 选择“字母识别”“收藏品抓取”或“球体抓取”。三个模式相互隔离，收藏品和球体模式不会执行字母播报。
3. 字母模式下让手掌完整进入画面并朝向摄像头；单手显示 A—E，双手通过左右手指数组合识别 A—Z。
4. 收藏模式下用拇指和食指捏合物品，移动后张开放下。
5. 球体模式下把手和前臂完整放进画面：慢速从球下方托起、用指尖侧向拨动、快速挥掌拍击，或捏合抓住后抛出。

建议环境光均匀、背景与手部颜色差异明显，摄像头距离以能完整看见双手和前臂为准。浏览器首次加载模型可能需要等待数秒。

## 系统架构

```text
摄像头视频（优先 1280×720 / 30fps）
  ↓ MediaDevices.getUserMedia
TensorFlow.js MediaPipe Hands（最多两只手、每手21个关键点）
  ├─ 手指数与左右位置 → 多帧平滑 → A—Z编码与语音
  ├─ 拇指/食指距离 → 捏合抓取与软体形变
  ├─ 掌边与指骨胶囊碰撞 → 球体接触物理
  └─ 手掌速度/角度/张开度 → 拍击、摩擦、涡流和力场

BlazePose Lite（球体模式按需加载）
  ↓ 肩、肘、腕、髋、膝关键点
身体线段碰撞

物理状态 → DOM球体位置、材质、情绪与粒子效果
```

页面不上传视频帧。手部与身体推理、物理计算、字母编码和画面合成都在浏览器本地完成。

## 核心技术实现

### 摄像头与坐标映射

`camera.js` 使用 `getUserMedia` 请求前置摄像头。视频和骨架Canvas使用相同尺寸；当页面通过 `object-fit: cover` 缩放视频时，交互层复算缩放比例和裁切偏移，把模型坐标准确映射到可见区域。切换模式时通过媒体轨道约束更新画面，不重复创建检测循环。

### 手势与字母识别

- 通过指尖、指节和手腕的相对距离判断每根手指是否伸出。
- 握拳直接得到0；单手1—5映射A—E；双手按画面左右排序后拼接数字，并把1—26映射为A—Z。
- 最近6帧采用多数表决，降低检测抖动；字母稳定变化后才调用Web Speech API播报。
- 捏合阈值按照掌宽动态缩放，使用进入/退出两套阈值和连续三帧松开确认；任意一只手捏合都会自动成为主交互手，避免双手顺序切换造成抓取中断。

### 真实手部—球体碰撞

左右手的21个关键点分别被连接成5根手指骨链、掌边胶囊和实心掌面，共同组成无明显空隙的碰撞体。每个关键点保存独立的自适应平滑速度，并按检测延迟短时预测位置；球体每一帧查找最近的指骨或掌面并执行：

1. 根据球心到骨段最近点计算接触法线和穿透深度。
2. 沿法线进行位置修正，避免快速挥手时球穿过手掌。
3. 使用“球速减局部手速”计算相对法向速度，并按材质恢复系数产生弹性冲量。
4. 沿接触切线施加材质相关摩擦，使球能被手掌带动、沿手指滚动或被侧向拨开。
5. 球位于缓慢移动的掌面上方时进入稳定支撑，手抽走后立即恢复重力下落。
6. 轻触即显示近手轮廓、方向性软体压缩和粒子，高速碰撞增强形变与光带；玻璃材质超过阈值会爆裂。
7. 手部直接接触后的短时间内暂停情绪漂移等自动运动，使球的结果优先对应真实手部动作。

张掌的逐帧碰撞只在实际接触时生效，不使用大范围隐形排斥。握拳引力、旋掌涡流、双手传送门等创意功能作为独立力场保留。

### 球体物理与视觉

- 球体状态包含位置、速度、尺寸、材质、情绪、极性以及各类冷却时间。
- 使用基于时间步长的重力、空气阻尼、侧边反弹和球间弹性碰撞；底部没有地面，离场后从顶部循环生成。
- 水球、果冻、玻璃、火焰、磁力和泡泡具有不同重力、阻尼、摩擦、弹性、漂浮或碎裂行为。
- 同材质软球可融合，双手拉伸可分裂；球还能与BlazePose生成的身体线段碰撞。
- 球壳使用低透明度彩色渐变表现玻璃包裹感，球内GIF/PNG保持100%不透明和原始色彩；移动球不再使用高开销的实时背景模糊。
- 粒子系统包含径向光点、星芒、方向光带、玻璃光晕拖尾和双层冲击环，并使用 `mix-blend-mode: screen` 形成发光叠加。粒子设有全局数量预算，高速拖尾降低生成频率，兼顾效果与流畅度。

### GPU与性能策略

- MediaPipe Hands与BlazePose在浏览器中使用WebGL推理；初始化时主动申请 `powerPreference: high-performance` 的WebGL2/WebGL上下文并记录实际显卡渲染器。
- 检测成功时 `body[data-compute-backend="webgl-gpu"]` 表示GPU路径可用；如果显示 `software-fallback`，需要在Chrome或Edge设置中开启“使用图形加速”。
- Canvas请求低延迟 `desynchronized` 上下文；身体姿态模型采用更低频的按需推理，为双手检测、GIF解码和实时碰撞留出GPU时间。
- 移动球体取消实时 `backdrop-filter`，使用透明渐变代替；粒子拖尾进行频率限制，降低GPU合成和DOM创建压力。

### 素材与界面层级

GIF与PNG均从本地素材目录加载。球内素材通过 `import.meta.glob` 建立池并洗牌轮换。三个模式都显示保留原始颜色的线条小狗背景贴纸，贴纸固定在页面两侧留白区域；贴纸层低于主面板且禁用指针事件，因此不会覆盖摄像头、Canvas或阻止交互。

## 调试与常见问题

- 摄像头打不开：确认地址为 `localhost` 或HTTPS，检查浏览器站点权限，并关闭正在独占摄像头的软件。
- 手势不稳定：增加正面光线，让手掌完整进入画面，避免手指互相遮挡。
- 球和手位置不一致：把浏览器缩放恢复为100%，刷新页面后重新启动摄像头。
- 页面更新未显示：使用 `Ctrl + F5` 强制刷新。
- 首次进入球体模式稍慢：身体模型采用按需加载，加载完成后会被浏览器缓存。
- 性能不足：关闭其他摄像头应用，降低浏览器窗口分辨率，或只保留一只手在画面中。
